# Скилл: Создание прототипа

Это главный скилл. Работа делится на 3 фазы: **Анализ → План → Реализация**.
Никогда не начинай писать код пока менеджер не подтвердил план.

В ответах менеджеру описывай цель, экраны, данные, действия и дизайн понятным
языком. Технические решения оставляй для реализации: не включай в ответы стек,
названия библиотек и компонентов UI Kit, файлы, команды и API. Например,
«таблица сотрудников» и «форма редактирования» описывают результат для пользователя.

---

## ФАЗА 1: АНАЛИЗ ТРЕБОВАНИЙ

### Шаг 1.1 — Прочитай ТЗ

Если менеджер передал путь до файла — прочитай его:
```
specs/{prototype-name}/requirements.md
```
Если передал текстом в промпте — работай с ним.

### Шаг 1.2 — Сформулируй своё понимание

Напиши менеджеру структурированное резюме:

```
## Я понял задачу так:

**Прototип:** [название]
**Цель:** [одна фраза — зачем это нужно]

**Экраны:**
1. [Название экрана] — [что делает пользователь]
2. ...

**Ключевые сценарии:**
- [Пользователь может ...]
- [Пользователь может ...]

**Данные которые отображаются:**
- [Сущность 1]: [поля]
- [Сущность 2]: [поля]
```

### Шаг 1.3 — Задай уточняющие вопросы

Задавай вопросы только если они влияют на реализацию. Не больше 3-5 вопросов за раз:

```
## Уточняющие вопросы:

1. [Вопрос о бизнес-логике которая неочевидна]
2. [Вопрос о приоритете функциональности]
3. [Вопрос о крайних случаях — что если список пустой?]
```

Примеры хороших вопросов:
- «Фильтрация применяется мгновенно или по кнопке?»
- «Что происходит после удаления — остаёмся на странице или уходим назад?»
- «Нужна ли пагинация или бесконечный скролл?»

### Шаг 1.4 — Предложи идеи по улучшению UX

Если видишь очевидные улучшения — предложи, но кратко:

```
## Идеи которые могут улучшить прototип:

💡 [Идея 1] — [почему это было бы удобно]
💡 [Идея 2] — [почему это было бы удобно]
```

### Шаг 1.5 — Дождись ответа менеджера

Не начинай план пока менеджер не ответил на вопросы. Если менеджер написал «всё верно» или «давай» — переходи к Фазе 2.

---

## ФАЗА 2: ПЛАН

### Шаг 2.1 — Составь и покажи план

```
## План прототипа

**Название:** {prototype-name}

### Экраны
- [Название экрана] — [что увидит пользователь и какие действия доступны]
- ...

### Действия и данные
- [Действие пользователя] — [ожидаемый результат]
- [Демонстрационные данные и проверка заполнения полей]
- ...

### Варианты дизайна
- Вариант A: [описание]
- Вариант B: [описание]

Оба варианта поддерживают одинаковые действия и общие данные.
Переключение дизайна сохраняет изменения. Интерфейс удобен на ноутбуке и телефоне.

Подтвердите план или напишите, что нужно изменить.
```

### Шаг 2.2 — Дождись подтверждения

Если менеджер написал «ок», «поехали», «давай» — переходи к Фазе 3.
Если попросил что-то изменить — скорректируй план и покажи снова.

---

## ФАЗА 3: РЕАЛИЗАЦИЯ

### Шаг 3.0 — Проверь UI-kit API

Если MCP `storybook` доступен в текущем runtime, вызови `list-all-documentation`, затем
для каждого незнакомого компонента последовательно вызови `get-documentation`.
Если MCP недоступен (локальный browser mode), используй проверенный snapshot в
`docs/skills/use-uikit.md` и TypeScript declarations установленного пакета.
Не угадывай API по памяти.

### Шаг 3.1 — Копирование и настройка шаблона

Скопируй `template/` в `prototypes/{prototype-name}/`.
В скопированных файлах замени `{prototype-name}` на реальное имя только в одном месте:
- `package.json` → поле `name` (например `@prototypes/crm-dashboard`) и `description`

Не изменяй `src/app/main.tsx` и `src/app/providers/index.tsx`: шаблон уже использует
React 19 `createRoot`, Router и корректный production bootstrap.

> `base: '/'` и `basename="/"` уже в шаблоне — менять не нужно.

### Шаг 3.2 — Реализация по слоям (последовательно)

Создавай файлы сам, слой за слоем — без субагентов.
В local browser mode проверки запускает backend после `PROTOTYPE_CODE_DONE`; агент не
запускает команды самостоятельно. В standalone режиме после каждого слоя запускай
`lint:fix` + `lint`, если host явно разрешает это.

> **Не запускай `npm install` во время написания кода** — он запускается автоматически на шаге 3.5. Ручной запуск посреди реализации только тратит время.

> `lint:fix` автоматически исправляет простые проблемы (неиспользуемые импорты, форматирование).
> Логические ошибки (`static-components`, `set-state-in-effect`) он не трогает — их
> исправляй руками, сверяясь с @docs/rules/code-style.md.

**Слой 1 — типы и моки:**
1. `src/shared/types/` — все TypeScript типы сущностей
2. `src/shared/api/` — MSW setup, хендлеры, моковые данные

```bash
cd prototypes/{prototype-name} && npm run lint:fix && npm run lint
```

**Слой 2 — сущности и общие компоненты:**
3. `src/entities/` — UI компоненты сущностей (используй @ai-sber/uikit)
4. `src/shared/ui/` — только если нужны общие обёртки

```bash
npm run lint:fix && npm run lint
```

**Слой 3 — фичи и страницы:**
5. `src/features/` — хуки, формы, бизнес-логика
6. `src/widgets/` — крупные блоки UI
7. `src/pages/` — страницы, подключение всего вместе

```bash
npm run lint:fix && npm run lint
```

### Шаг 3.3 — Variant Switcher

Смотри @docs/skills/variant-switcher.md
Создай 2-3 варианта для ключевого экрана прototипа.

### Шаг 3.4 — Подключение роутинга

В `src/app/App.tsx` подключи все страницы.
В `src/shared/api/handlers.ts` подключи все MSW хендлеры.

### Шаг 3.5 — Финальная проверка кода

```bash
cd prototypes/{prototype-name}
npm install
npm run type-check    # 0 ошибок
npm run lint          # 0 warnings
```

Если что-то упало — исправь до следующего шага.

**Отдельно проверь интерактивность:** пройдись по всем хукам в `src/**/model/*.ts`, которые
дёргают `fetch('/api/...')` — у каждого должна быть dual-mode ветка `import.meta.env.DEV`
(см. `docs/skills/mock-api.md`). Без неё прототип в собранном виде (не `vite dev`) будет вёрсткой
без единой рабочей кнопки — MSW там не запускается.

### Шаг 3.6 — Показ менеджеру

Смотри @docs/skills/export-html.md.

```bash
node scripts/export-html.mjs {prototype-name}
```

Собирает прототип в один самодостаточный HTML-файл и открывает его в браузере менеджера
(`open`) — без сервера, без сети. Сообщи:

```
## 👀 Прототип готов!

Открылся в браузере. Посмотри и напиши — всё устраивает?

### Что реализовано:
- [список страниц и ключевых функций]

### 🎨 Варианты дизайна:
Переключатель встроен — кнопка в правом нижнем углу.
```

Дождись ответа менеджера. Если попросил правки — внеси их, повтори `npm run type-check`/`npm run lint`
и снова вызови `/export-html` — файл пересоберётся и откроется заново.

Если менеджеру нужно поделиться ссылкой с кем-то удалённо (не просто посмотреть самому) —
смотри @docs/skills/open-in-csb.md как альтернативу.

### Шаг 3.7 — Итоговый отчёт

```
## ✅ Прototип готов и проверен на сборке!

### Что реализовано:
- [список страниц и ключевых функций]

### 🎨 Варианты дизайна:
Переключатель встроен прямо в прototип — кнопка в правом нижнем углу.

### 🔌 Для разработчика (что нужно на бекенде):
| Метод | URL | Описание |
|-------|-----|----------|
| GET | /api/... | ... |
```
